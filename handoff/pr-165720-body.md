## What Problem This Solves

Fixes: code snippets sent with `openclaw message send` or the agent message tool lose their `\n` escapes when the message has more than one line. A fenced `printf("%d\n", x);` reaches the channel with a real line break inside the string literal.

## User Impact

User impact: multi-line messages, including code blocks, are delivered with literal `\n` sequences intact. Single-line messages such as `--message 'line one\nline two'` still expand `\n` into a line break, as before.

One behavior changes on purpose: a message that already has real line breaks and also contains a literal `\n` meant as a line break now keeps the literal text. A sender who wants a line break there can use a real newline.

This leaves the single-line expansion discussed in #123132 unchanged. Fully over-escaped output still arrives as single-line text and still expands.

## Why This Change Was Made

The message send action replaced every literal `\n` with a real line break. That expansion is meant for single-line input, such as a shell `--message` flag or tool input where a model escaped every newline. Applying it to text that already has real line breaks rewrote code content before any channel saw it. The channel adapter received a real line break inside the string literal, and IRC, which flattens line breaks, showed it as a space.

The send action now expands escaped newlines only when the text has no real line breaks. This is the only place in core that does this expansion, so every route (CLI, agent message tool, cron delivery) gets the same behavior.

## Evidence

**Live check on the latest release.** I ran a local IRC server (miniircd) with a second client in `#room`, and used the published `openclaw@2026.9.8` CLI with isolated state. The installed IRC plugin already carried the separate IRC backslash fix, so IRC wasn't touching `\n` and any change below comes from core. I sent this multi-line message:

````text
Fix:
```c
printf("%d\n", x);
```
````

The other client received:

```text
BEFORE  (openclaw 2026.9.8 as published)
:clawbot!clawbot@127.0.0.1 PRIVMSG #room :Fix:  printf("%d ", x);

AFTER   (same release, newline expansion changed as in this PR)
:clawbot!clawbot@127.0.0.1 PRIVMSG #room :Fix:  printf("%d\n", x);

Single-line CLI convenience, after the change (IRC flattens line breaks to spaces)
--message 'line one\nline two'  ->  :clawbot!clawbot@127.0.0.1 PRIVMSG #room :line one line two
```
